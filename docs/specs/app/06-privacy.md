# 06. 個人データの取り扱い

Loggify は、第三者（エンドユーザー）の位置情報・IP・端末情報を扱う。
「何を・なぜ・いつまで・誰が見られるか」をアプリの仕様として固定し、プライバシーポリシーと利用規約はこの内容に合わせて書く。

> 本章は設計上の方針であり、法的な助言ではない。公開前にプライバシーポリシーと利用規約について専門家の確認を受けること。

## 1. 役割の整理

| 立場 | 主体 | 責任 |
|---|---|---|
| データを使う目的を決める者 | サーバーの運営者（組織） | 自サーバーで何を収集するかを設定し、メンバーへ周知する |
| 処理を受託する者 | Loggify | 設定どおりに収集・保存・削除し、安全に管理する |

利用規約で、組織が上記の責任を負うことに同意させる（サーバー登録時に同意のチェックを求める）。

## 2. データ一覧

| データ | 取得元 | 目的 | 必須 | 保存期間 |
|---|---|---|---|---|
| Discord ID・ユーザー名・表示名・アバター | Discord OAuth | 本人の特定・ロール付与 | 必須 | ログの保存期間中（要約レコードとして残る） |
| メールアドレス | Discord OAuth | サーバー運営者が求める場合のみ | 任意（サーバー設定） | 詳細（既定 90 日） |
| 認証結果・ASN・ASN 判定・国 | サーバー処理・ipinfo | VPN 判定・不正対策・集計 | 必須 | 要約（ログを削除するまで） |
| IP アドレス・ISP・地域・都市 | リクエスト・ipinfo | 不正対策（複数アカウントの検知） | 必須 | 詳細（既定 90 日） |
| GPS 座標・精度・住所 | ブラウザの Geolocation API・逆ジオコーディング | サーバー運営者が求める場合のみ | サーバー設定（既定 `optional`。拒否しても認証は継続） | 詳細（既定 90 日） |
| 画面サイズ・User-Agent | ブラウザ | 不正対策 | 必須 | 詳細（既定 90 日） |
| フィンガープリント（合成ハッシュ + 生の値: webgl_renderer・webgl_vendor・canvas_hash 等） | FingerprintJS | 複数アカウントの検知 | 必須 | 詳細（既定 90 日） |
| Discord のアクセス・リフレッシュトークン | Discord OAuth | ユーザー情報の取得 | — | **保存しない**（取得後すぐに破棄） |

- 「詳細」は `verification_logs` のうち 04 で ✓ を付けたフィールド。保存期間を過ぎると NULL にする
- 「要約」は Discord ID・結果・国・ASN・日時。個人データの削除要求、または削除済みサーバーの 30 日経過で物理削除する
- フィンガープリントは合成ハッシュに加え、WebGL レンダラー文字列・Canvas ハッシュなどの生の値も保存する（D3。複数アカウント検知の精度を優先し、正体を特定できる氏名・連絡先とは扱いが異なるものとして許容している）

## 3. 同意

### 3.1 認証開始ページ（`/v/[serverId]`）の表示内容

- どのサーバーのための認証か（サーバー名・アイコン）
- 収集する項目の一覧（そのサーバーの設定に合わせて出し分ける。GPS・メールはオンのときだけ表示）
- 目的・保存期間・閲覧できる人（そのサーバーの運営者と Loggify の運営者）
- 削除の依頼先（サーバーの運営者、または Loggify の問い合わせ窓口）
- プライバシーポリシーへのリンク
- 「同意して Discord でログイン」ボタン。同意しない場合は認証に進めない

### 3.2 同意のバージョン管理

- 同意文言のバージョン = `{文言のバージョン}-{サーバー設定のハッシュ}`（例: `v1-3fa2`）
  - 文言が変わったとき、またはサーバーの収集設定（GPS・メール）が変わったときに値が変わる
- start 時に、ユーザーが見ていたバージョンと現在のバージョンを照合し、違っていれば同意画面へ戻す
- ログの `consent_version` に記録し、「どの説明を見て同意したか」を後から確認できるようにする

### 3.3 GPS

- ブラウザの位置情報ダイアログは、同意画面を経た後の `/verify` でのみ出す
- 既定値は `optional`。拒否されても認証は続ける（`location = null`）
- サーバー設定で `required` にした場合、拒否されたら `declined` にする。同意画面に「位置情報の許可が必要」と明記する
- `off` にすれば GPS ダイアログ自体を出さない

## 4. アクセス権

| 誰が | 見られる範囲 |
|---|---|
| 組織のメンバー（viewer 以上） | 自組織のサーバーのログ（詳細を含む） |
| システム管理者 | 全組織のログ。閲覧はすべて `audit_logs` に記録する（D7）。障害調査・不正利用の調査に限る |
| エンドユーザー本人 | MVP ではセルフサービスで閲覧する手段はない。問い合わせで対応する |

- 通知（Discord Webhook）には**認証結果・国・VPN 判定・Discord ユーザー情報（ID・username・global_name）・メールアドレス（収集時）・ダッシュボードへのリンクのみ**を含める。IP・ISP・地域/都市・GPS座標・住所・画面サイズ・User-Agent・フィンガープリントは含めない（D8）。Webhook の URL を知っていれば誰でも見られ、保存期間の管理も効かないため
- CSV エクスポート（Post-MVP）を作る場合は admin 以上に限定し、監査ログに記録する
- アプリケーションログ（stdout）には IP・GPS・トークン・メールを出さない。リクエストログの IP は出力しないか、マスクする（`203.0.113.x`）

## 5. 削除

| きっかけ | 処理 |
|---|---|
| 保存期間の経過 | 詳細フィールドを NULL にする（1 時間ごとのバッチ） |
| 組織からの削除要求（Discord ID 指定） | その組織のその Discord ID のログをすべて物理削除し、`audit_logs` に `data_erasure.create` を記録（Discord ID は記録しない） |
| エンドユーザーから Loggify への削除要求 | システム管理者が本人確認（Discord OAuth でログインしてもらう）のうえ、全組織のその Discord ID のログを物理削除 |
| サーバーの削除 | 論理削除から 30 日後にログを物理削除（誤操作から復旧できる期間） |
| 組織の削除 | 配下のサーバーを論理削除 → 上と同じ |
| システムユーザーの削除 | `system_users` を匿名化し、セッション・Passkey・所属を削除 |

バックアップに残ったデータは、バックアップの保持期間（インフラ設計で決める。35 日以内を推奨）の満了で消える。プライバシーポリシーにその旨を書く。

## 6. セキュリティ上の対策（個人データ関連）

- 詳細個人データを含む API（`GET /logs/{id}`）のレスポンスには `Cache-Control: no-store` を付ける
- 秘密値（Client Secret・Bot Token・Webhook URL・Telegram の token）はアプリ側で暗号化して保存する（04 §4）
- DB は閉域ネットワークに置く（インフラ設計）
- 保存時の暗号化は DB の機能（TDE 相当）に任せ、アプリ側で個別フィールドの暗号化はしない（検索のため）
